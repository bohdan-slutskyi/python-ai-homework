# Агент для поиска ошибок в Python-коде

## Идея и польза

Предлагается агент, который помогает находить ошибки в небольших учебных
Python-проектах и объясняет возможные исправления понятным языком. Пользователь
передаёт задачу, например: «Почему функция неверно обрабатывает пустой список?»,
и указывает файл с кодом. При наличии можно приложить текст ошибки и ожидаемый
результат.

Такой помощник полезен при изучении Python и веб-разработки: он сокращает время
поиска причины ошибки и помогает понять её, сохраняя за пользователем решение
о внесении изменений.

## Инструменты

| Инструмент | Что делает | Что возвращает |
| --- | --- | --- |
| Чтение файла | Читает выбранный пользователем файл проекта | Код с номерами строк |
| Поиск по проекту | Ищет определения и вызовы функции в разрешённой папке | Имена файлов и подходящие строки |
| Проверка синтаксиса | Проверяет, можно ли разобрать Python-код без выполнения программы | Сообщение об ошибке с номером строки либо отсутствие синтаксических ошибок |
| Статический анализ | Запускает настроенный в проекте Ruff для поиска типовых проблем | Диагностику, например сведения о неопределённом имени или неиспользуемом импорте |
| Запуск тестов | Выполняет выбранные существующие тесты в отдельном тестовом окружении после разрешения пользователя | Результаты тестов и сообщения о сбоях |

Каждый инструмент представляет собой функцию с понятным описанием назначения,
входных параметров и результата. Модель использует эти описания, чтобы выбрать
подходящий инструмент. Например, чтение файла получает путь, а поиск — строку
для поиска и папку проекта. Если Ruff или тестовая среда отсутствуют, агент
сообщает об этом; автоматическая установка не предусмотрена.

## Как работает агент

1. Пользователь описывает проблему и указывает разрешённые файлы. Если неясно,
   какое поведение ожидается, агент задаёт уточняющий вопрос.
2. Языковая модель анализирует запрос и выбирает нужное действие. Для сообщения
   о синтаксической ошибке полезна проверка синтаксиса; для неверного результата
   функции нужны чтение кода и анализ примеров входных данных.
3. Программа выполняет выбранную функцию и возвращает результат модели.
   При необходимости агент делает следующий шаг: например, находит вызовы
   проблемной функции или использует статический анализ.
4. Если существующие тесты могут помочь, агент предлагает подходящую проверку
   и после разрешения пользователя запускает её в тестовом окружении.
5. Модель сопоставляет запрос, код и результаты инструментов. В ответе указывает
   место ошибки, объясняет причину и предлагает минимальное исправление.
   Подтверждённые результаты проверок отделяются от предположений.
6. Пользователь самостоятельно применяет исправление. После этого можно
   повторить ту же проверку и сравнить результат.

Последовательность инструментов заранее не фиксируется: модель выбирает
следующее действие по задаче и уже полученным результатам. В этом заключается
отличие предлагаемого агента от скрипта, который всегда выполняет один и тот
же набор проверок.

## Пример использования

Пользователь сообщает: «Функция среднего значения падает на пустом списке».
В указанном файле находится выражение `sum(values) / len(values)`.

Агент читает функцию и замечает возможное деление на ноль. Он уточняет,
что должно происходить при пустом списке. Если требуется понятное сообщение
об ошибке, предлагает перед вычислением проверить список и вызвать
`ValueError` с объяснением. Если в проекте уже есть соответствующий тест,
его результат можно использовать для подтверждения проблемы и проверки
исправления. Без запуска теста вывод обозначается как результат анализа кода,
а не как подтверждённый эксперимент.

## Память и ограничения

В рамках диалога сохраняются исходная задача, ожидаемое поведение, просмотренные
фрагменты и результаты проверок. Это позволяет понять запрос «Проверь теперь
случай с одним элементом» без повторения всей задачи. Для разных проектов
история разделяется, а устаревший код после изменения читается заново.

Модель может ошибаться; успешная проверка синтаксиса или прохождение тестов
не доказывают отсутствие всех ошибок. Агент не изменяет файлы и не публикует
код самостоятельно. Доступ ограничивается выбранным проектом, файлы ключей
и паролей исключаются из чтения и передачи модели. При использовании внешнего
API разрешённый код отправляется провайдеру только с согласия пользователя.
Тесты могут выполнять произвольный код, поэтому их запуск ограничивается
согласованной тестовой средой.

Это описание предлагаемой системы. Реализация агента и результаты его запуска
в данной работе не заявляются.
